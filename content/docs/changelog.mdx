## Unreleased

**Fixes in `@copybook/cli`:**

- `copybook init` names the project's config file in the `AGENTS.md` section, such as `copybook.config.mjs`. It used to say `copybook.config.ts` for every project.

## 0.3.0

Released November 5, 2026.

Prompts can be plain Markdown files, such as the ones a docs site serves at `/prompts/*.md`, with no change to the files. See [Markdown prompts](/docs/guides/markdown-prompts).

**Breaking changes**, in `@copybook/cli`:

- `copybook test` syntax-checks the literal `bash`, `sh`, `shell`, and `zsh` code blocks in prompts, such as `t.code("bash", ...)`, like it checks literal commands. A prompt with a broken or placeholder-filled shell block now fails `test`.

**New in `@copybook/core`:**

- `definePrompt({ id, markdown })` defines a prompt from Markdown text, which renders exactly as written. Fenced code blocks become `code` nodes, with the rest of the info string, such as `title="db.ts"`, in the new `meta` field.
- CommonJS code can `require("@copybook/core")` on Node.js 20.19+ and 22.12+, which load ES modules from `require`. Before, the package's exports only matched `import`, so `require` failed with `ERR_PACKAGE_PATH_NOT_EXPORTED`.

**New in `@copybook/cli`:**

- `markdown` in the config turns a directory of Markdown files into prompts, with ids from their paths. Frontmatter stays part of the prompt unless you set `frontmatter: "strip"`, and `meta` sets metadata for single files. `content` is optional when `markdown` is set.
- Each Markdown file is its own snapshot. `snapshot` doesn't write a copy, `check` never reports one stale, and history, `report` diffs, `list --changed`, and `check --base` read the file's own git changes. Renaming a file without an alias is reported like any removed id.
- With a source's `url` set, usage scanning finds a Markdown prompt in any `usage.include` file that contains its URL, Markdown and MDX included. Only JS and TS files are parsed for imports.
- `defineEval` takes a prompt's id as well as the prompt, and `eval` warns about a spec whose id isn't a prompt instead of skipping it.
- `status --json` lists the Markdown directories in `config.markdown`, and `show`, the MCP server, and Studio show a Markdown prompt's file as its source.

**Fixes in `@copybook/cli`:**

- `check --base`, `report`, and `list --changed` no longer fail with "outside repository" when the project's path goes through a symlink.

## 0.2.0

Released November 3, 2026.

Copybook is now built for coding agents: every surface tells an agent what exists, what needs doing, and which command or tool does each step. See [Coding agents](/docs/guides/agents).

**Breaking changes**, all in `@copybook/cli`:

- A command that couldn't run now exits with 2 instead of 1: no config, a bad option, content that fails to load, an unknown id or bad values, or `eval` outside CI. Commands that ran and found problems still exit with 1, so scripts that check for a non-zero code are unaffected.
- `copybook init` no longer fails when `copybook.config.ts` exists. It keeps the config, only changes what's out of date, and sets up coding agents unless you pass `--no-agent`.
- Studio's API errors are `{ error: { code, message }, next }` instead of `{ error }`, with 400, 404, 405, 413, 415, and 422 instead of 500. POSTs must send `Content-Type: application/json`, and while Studio listens on localhost, requests must be for a localhost host.
- `--reporter` rejects values other than `pretty`, `json`, and `junit` instead of falling back to JSON.

**New in `@copybook/cli`:**

- `copybook status` shows the config, the definitions, snapshot states, issues, the latest test and eval results, and what to do next. `status --json` is where agents start, and `copybook --help` says so.
- `copybook show <id>` prints one definition as Markdown: where it's declared and rendered, what it embeds and what embeds it, its params, its output for every variant, its latest test and eval results, and its snapshot history. `--values` renders with your own values, `--text` prints just the output, and `--json` everything. Old ids resolve through aliases, and typos get suggestions.
- `list --grep <text>` finds the definitions whose id, title, placements, tags, or rendered output contain the text. `list --json` adds each definition's snapshot state, embedders, and rendering files, plus the validation issues.
- Every command except `report` takes `--json`. The output has `schemaVersion`, `ok`, and `next`: the steps to take, each with its command, MCP tool, affected ids, and whether an agent can take it without asking. `check --json` includes the snapshot diffs. When a command fails, `--json` prints `{ ok: false, error: { code, message }, next }`, and without `--json` the error ends with the next step to run.
- `copybook commands --json` describes every command and flag, with what each one does to the project and whether an agent can run it without asking. The same catalog ships as `@copybook/cli/catalog.json`.
- `copybook mcp` serves the project to coding agents over MCP, on stdio. Its tools are `status`, `find_definitions`, `get_definition`, `render`, `check`, `write_snapshots`, `prune_snapshots`, and `run_tests` (syntax and typecheck), each annotated as read-only or writing, and its instructions tell the agent where to start. It starts before `copybook init`, keeps stdout for the protocol, follows file changes, and exits when the client closes stdin.
- `copybook init` sets up coding agents. It adds a Copybook section to `AGENTS.md` (and to `CLAUDE.md` when that doesn't import `AGENTS.md`), writes the Copybook skill to `.agents/skills/copybook` and `.claude/skills/copybook`, registers the MCP server in `.mcp.json` (and `.cursor/mcp.json` or `.vscode/mcp.json` when those exist), ignores `.copybook/`, and prints the Codex command. Packages already in `package.json` aren't installed again, agent files only change between their markers or keys, and `--dry-run` shows what would change. The same skill installs with `npx skills add neon-solutions/copybook`.
- Studio has an Agents view: what to do next, with a Run button for writing snapshots and the safe tests, the commands to connect Claude Code, Codex, or any MCP client, and every CLI command with whether agents can run it. Each definition has a Copy for agent button that copies it as Markdown, and warnings show next to errors.
- Studio's API is for agents too. `GET /api` lists every endpoint, `/llms.txt` explains them, and `/` serves that guide to requests that prefer Markdown. New endpoints: `/api/status`, `/api/commands`, `/api/definitions/{id}`, and `/api/definitions/{id}.md`. `studio --json` prints its URLs as one line once it's listening.
- Studio can write snapshots (`POST /api/snapshot`) and run the syntax and typecheck tests (`POST /api/test`). Tests run in the background: the request answers 202 with a `runId`, results stream as `test` and `test-done` events, and a second run waits with 409. The run tier and evals stay in the CLI, both writes are off when Studio listens beyond localhost, and it warns when `--host` exposes it to other machines.
- `test --json` is short for `--reporter json`. `test` and `eval` warn about `--only` ids that match nothing, and their human output ends with the next steps.
- Colors follow the output. They're off when stdout isn't a terminal, even when `CI` is set, and with `--json` or `NO_COLOR`.
- `runCli`, `CopybookError`, the project analysis behind `check` (`analyzeProject`, `checkIssues`, `findDefinition`, `searchDefinitions`), `buildStatus`, `definitionDetail`, and `buildCatalog` are exported. Every `Issue` has a `code`.

**Fixes in `@copybook/cli`:**

- Loading the same project from two processes at once, such as Studio and `check`, no longer fails now and then with "must default-export defineConfig". The bundle cache is written atomically.
- Studio no longer reloads when tests write their results, and reloads run one at a time, so an older load can't replace a newer one.

## 0.1.1

Released November 2, 2026.

- **`@copybook/cli`**: `test` and `eval` no longer crash with `EPIPE` when a command exits before reading its input.
- Both packages link to copybook.dev and the issue tracker from npm. Their READMEs link to the docs and describe the 0.x compatibility policy.
- **`@copybook/cli`**: `copybook --help` and `copybook init` link to the docs at copybook.dev.

## 0.1.0

Released November 2, 2026. The first release.

- **`@copybook/core`**:
  - `defineCommand`, `defineSnippet` (with dimensioned variants), `definePrompt`, and `defineCollection`
  - the `p` param builders, with examples, defaults, secrets, and Standard Schema
  - the `t` template tag, with param nodes and `t.cmd`, `t.code`, and `t.include` embeds
  - `render`, `renderExample`, `listVariants`, `toText`, `toSegments`, `collectCommands`, and `collectEmbeds`
- **`@copybook/cli`**:
  - `init`, `list`, `snapshot`, and `check`, with rendered Markdown snapshots and `--changed` change detection
  - `test`, with syntax, typecheck, and run tiers, fixtures, and JSON and JUnit reports
  - `eval`, with agent adapters (`literal`, `claude-code`, `codex`), PATH shims, assertions, trials, budgets, and history
  - `usages` and `report`, which show where product code renders each definition and summarize pull request changes
  - `studio`, a local UI for browsing, previewing, and tracing definitions, with test and eval results
- **Registry**: Agent Prompt, Code Variants, Command Tabs, Copy Button, and Rendered Text.
