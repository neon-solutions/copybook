## Definitions

| Export | Description |
| --- | --- |
| `defineCommand(input)` | A shell command. `verify` defaults to `"syntax"`. |
| `defineSnippet(input)` | A code block, either single (`lang` + `template` or `code`) or with `dimensions` and `variants`. |
| `definePrompt(input)` | Text for a coding agent, from a `template` or from `markdown` text, which renders exactly as written. |
| `defineCollection({ idPrefix, items, key, build })` | Definitions generated from data, with ids `<idPrefix>.<key>`. |
| `skip(reason)` | A `verify` value that never runs the definition. |
| `isDefinition(value)`, `isCollection(value)`, `isFragment(value)` | Type guards based on the brands. A fragment is what a `t` template returns. |
| `variantKey(dimensions, when)` | Builds a canonical variant key. |

Definitions are frozen objects branded with `DEFINITION` (`Symbol.for("copybook.def")`). Collections are branded with `COLLECTION`, and fragments with `FRAGMENT`.

## Params

`p.string()`, `p.url()`, `p.number()`, `p.boolean()`, `p.enum(values)`, `p.secret({ placeholder, env? })`, and `p.schema(standardSchema)`. Each returns a `Param` with `.example()`, `.default()`, `.optional()`, `.describe()`, and `.toJSON()`.

`InputValues<S>` is the type `render` accepts. `TemplateValues<S>` is the type a template receives.

## Rendering

| Export | Description |
| --- | --- |
| `render(definition, values?, options?)` | Renders with real values. Throws if a required param is missing. |
| `renderExample(definition, { values?, variant? })` | Renders with example values, filling in any `values` you pass. |
| `selectVariant(snippet, selection?)` | Returns the matching variant, or throws. |
| `listVariants(snippet)` | Every variant as `{ key, label, when, lang? }`, in declaration order. `label` joins the option labels, such as `AI SDK · .env`. |
| `toText(rendered, { format? })` | The text to copy. `format` is `"markdown"` (default) or `"plain"`. |
| `toSegments(rendered, { format? })` | Flat segments for highlighted UIs. |
| `collectCommands(rendered)` | Every embedded command, as `{ id?, text }`. |
| `collectEmbeds(rendered)` | The ids of every embedded definition. |

## The rendered tree

```ts
interface Rendered {
  id: string;
  kind: "command" | "prompt" | "snippet";
  lang?: string; // snippets
  variant?: string; // snippets with variants
  nodes: Node[];
}

type Node =
  | { type: "text"; value: string }
  | {
      type: "param";
      name: string;
      value: string;
      secret?: true;
      placeholder?: true;
    }
  | { type: "command"; id?: string; children: Node[] }
  | {
      type: "code";
      id?: string;
      lang?: string;
      meta?: string; // the rest of a Markdown fence's info string
      variant?: string;
      children: Node[];
    }
  | { type: "include"; id: string; kind: DefinitionKind; children: Node[] };
```

`Rendered` is plain JSON. Render on the server and pass it to client components.

## Blocks

`@copybook/core/blocks` exports `toBlocks(rendered)`, which parses a prompt's Markdown into blocks for a formatted view, such as the components' rendered view. It's a separate entry, so apps that only copy text don't load it.

| Block           | Fields                                                     |
| --------------- | ---------------------------------------------------------- |
| `heading`       | `level` (1 to 6), `children`                               |
| `paragraph`     | `children`                                                 |
| `list`          | `ordered`, `start?`, `items: { children: Block[] }[]`      |
| `code`          | `lang?`, `meta?`, `id?`, `children` (text and params)      |
| `command`       | `id?`, `children`, for an embedded command on its own line |
| `blockquote`    | `children: Block[]`                                        |
| `thematicBreak` |                                                            |

Inline `children` are `text`, `param` (with `name`, `secret?`, `placeholder?`), `inlineCode` (`command: true` for embedded commands), `strong`, `emphasis`, and `link` (`href`). Params and commands are never read as Markdown. Links with schemes other than `http`, `https`, and `mailto` stay text, and Markdown that `toBlocks` doesn't know, such as tables, stays paragraph text. Frontmatter kept in a Markdown prompt becomes a `yaml` code block.

## Fill

`@copybook/core/fill` lets readers fill in params in the browser, without the definition.

- `listParams(rendered)` returns each param once, in the order they first appear: `{ name, value, secret?, placeholder? }`.
- `fillParams(rendered, values)` returns a new tree in which every param named in `values` has that value, in embedded definitions too. A filled secret loses `placeholder`, and empty values are ignored.

```ts
import { renderExample } from "@copybook/core";
import { fillParams } from "@copybook/core/fill";

const rendered = fillParams(renderExample(setUpWithAgent), {
  orgId: "org-123",
});
```

Only params interpolated directly into a template are param nodes, so text the template derives from a param doesn't change.
